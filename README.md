# 🏠 Stay:Care

> AI 가 귀가 순간부터 사용자의 건강 루틴을 개인화해 관리해주는 홈 웰니스 서비스

## 📖 서비스 소개

Stay:Care는 **집에 도착하는 순간부터 AI가 사용자의 건강 루틴을 개인화해 관리해주는 홈 웰니스 서비스**입니다.

단순히 정해진 시간에 알림을 보내는 기존 웰니스 앱과 달리, **귀가(Wi-Fi), 날씨, 개인 캘린더 일정, 1분 자가 진단**을 종합적으로 분석하여 지금 가장 필요한 맞춤형 루틴을 제안합니다.

- **귀가 순간**을 인식하여 적절한 홈케어 루틴 제공
- **실시간 날씨**와 사용자 컨디션을 반영한 AI 맞춤 미션 추천
- **개인 캘린더**와 연동하여 중요한 일정(D-Day)에 맞춘 집중 케어
- **7일 · 14일 · 21일 · 28일** 목표 코스를 통해 건강한 습관 형성
- **스탬프 지도**로 진행 상황을 시각화하여 꾸준한 루틴 유지

Stay:Care는 사용자의 일상 속 가장 자연스러운 순간인 "**귀가**"를 중심으로,
AI 가 건강한 습관을 부담 없이 이어갈 수 있도록 도와주는 개인 맞춤형 홈 웰니스 비서입니다.

## ✨ 주요 기능

| 기능 | 설명 |
| :--- | :--- |
| 🩺 **1분 컨디션 진단** | 나이, 수면 시간, 피부 타입, 야외 활동 시간 등을 기반으로 현재 컨디션을 분석하고 맞춤형 케어를 제공합니다. |
| 🎯 **기간별 목표 코스** | 7일, 14일, 21일, 28일 코스를 선택하여 목적에 맞는 웰니스 루틴을 제공합니다. |
| 🏠 **귀가 감지 AI 미션** | Wi-Fi 연결을 통해 귀가를 인식하고, 가장 적절한 홈케어 미션을 추천합니다. |
| 📅 **캘린더 연동** | 결혼식, 면접, 회식 등 중요한 일정을 반영하여 AI가 미션을 자동으로 재구성합니다. |
| 🌤️ **실시간 환경 분석** | 날씨 및 외부 환경 데이터를 분석하여 수분 섭취, 피부 진정 등 필요한 루틴을 추천합니다. |
| 🗺️ **스탬프 지도** | 매일의 미션 완료 현황을 지도 형태로 시각화하여 목표 달성 과정을 한눈에 확인할 수 있습니다. |
| 📈 **성장 리포트 (Premium)** | 누적된 데이터를 기반으로 미션 달성률과 피부 컨디션 변화를 그래프로 제공합니다. |

## 🎯 Git Convention

- 🎉 **Start** : Start New Project [:tada:]
- ✨ **Feat** : 새로운 기능 추가 [:sparkles:]
- 🐛 **Fix** : 버그 수정 [:bug:]
- 🎨 **Design** : CSS 등 사용자 UI 디자인 변경 [:art:]
- ♻️ **Refactor** : 코드 리팩토링 [:recycle:]
- 🔧 **Settings** : 설정 파일 수정 [:wrench:]
- 🗃️ **Comment** : 필요한 주석 추가 및 변경 [:card_file_box:]
- ➕ **Dependency/Plugin** : 라이브러리 추가 [:heavy_plus_sign:]
- 📝 **Docs** : 문서 수정 [:memo:]
- 🔀 **Merge** : 브랜치 병합 [:twisted_rightwards_arrows:]
- 🚀 **Deploy** : 배포 관련 작업 [:rocket:]
- 🚚 **Rename** : 파일 및 폴더 이름 수정 [:truck:]
- 🔥 **Remove** : 파일 삭제 [:fire:]
- ⏪️ **Revert** : 이전 버전으로 롤백 [:rewind:]

## 🌲 Branch Convention

- `main` : 배포 가능한 브랜치
- `develop` : 개발 브랜치
- `feat/#이슈번호/명칭` : 새로운 기능 개발 브랜치
    - 예시 : `feat/#12/login`
- `ui/#이슈번호/명칭` : UI 작업 브랜치
    - 예시 : `ui/#12/home`
- `refactor/#이슈번호/명칭` : 리팩토링 작업 브랜치
    - 예시 : `refactor/#12/component-structure`

## 🌊 Flow

1. Issue 생성
2. 최신 `develop` 브랜치에서 작업 브랜치 생성
3. 기능 개발 및 커밋 진행
4. `develop` 브랜치로 Pull Request 생성
5. 코드 리뷰 진행
6. 리뷰 완료 후 `develop` 브랜치로 병합
7. 병합 완료 후 작업 브랜치 삭제
